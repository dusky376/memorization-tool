## 实际踩坑记录
1. **WXML 表达式里写不了 `{{词}}` 字面量（最先踩）**：`{{ '{{词}}' }}` 想在页面上展示标记语法，WXML 解析见字符串里第一个 `}}` 就收口表达式，直接截断错误。**对策**：字面量经 data 绑定（`data.mN='{{词}}'` → `{{mN}}`）；测试脚本里也一律 `String.fromCharCode(123,123)` 构造。已蒸馏 G-0030。
2. **WXML 不是 HTML**：`<small>`、`<br>`、`<span>` 都不是组件（第一个加页直接用了）。**对策**：全部换 `<view>`/`<text>` + 类名（.dropsub/.phint/.igreason…），tip 文案里换行拆成多个 `<view>`。
3. **tabBar 页不能 navigateTo 带参**：管理页「编辑」要把词条 id 带到录入页，而录入页是 tab 页，`navigateTo` 静默打不开。**对策**：`app.globalData.editId` + `wx.switchTab`，录入页 onShow 消费后清空。
4. **wx.uploadFile 与 wx.request 返回类型不一致**：`request` 拿到的 `res.data` 已是对象，`uploadFile` 拿到的 `res.data` 是**字符串**，必须手动 `JSON.parse`（api.js upload 里 try/catch 包好给出可读错误）。
5. **"疑似重复"是 HTTP 200 + `j.dup`**：不是 4xx，客户端必须按业务字段判断（加页保存、整理页入库两处都先查 dup 再弹确认窗强制二次提交）。
6. **测试脚本自己制造 6 个假失败**：第一版 api.test.js 有三处输入字符串丢了 `{{ }}` 字面量、两处预期值算错（「核心」2 字 → `w=2+2=4`；autoMark 统一包 `{{!}}` 红标样式）。api.js 全部 60 断言全对，**坑全在测试代码里**。规律：测试脚本失败先怀疑测试本身，尤其涉及字面量/字符宽度这类容易手算的。
7. **鸿蒙 compatibility 无法检索确认**（websearch 两次 cancelled）→ 改**防御式兼容**：`typeof wx.chooseMessageFile === 'function'` 探测后再显示入口；`showModal editable` 拿不到输入时给明确提示；所有请求失败 failToast 明示原因。个别 API 真机若报错，先查鸿蒙微信支持列表。
8. **picker 双层盒子双边框**：.frow 里 picker 自带盒 + 子 view.formpick 又一层。**对策**：追加 `.frow > picker { border:none; background:transparent }` 覆盖规则，盒子统一收口到 .formpick。
9. **flex 里 auto 外边距会被第二次拉扯**：`margin-left:auto` 想右对齐一个 picker，同一行放两个都带 auto 会把剩余空间劈成两半，第一个反而居中。管理页两个筛选 picker 干脆去掉 auto 左对齐。

## 复利
- **逻辑全在 utils/api.js，页面只做 setData**：挖空解析/宽度/校对/自动标红全是纯函数，node 直接 60 断言测完，模拟器里主要测交互与网络，逻辑不反复手点。
- **渲染不用 rich-text**（不可交互、事件进不去）：prepareInto 把文本拆成 `{t:'txt'|'blank', s, hot, key, w, inp}` 分段数据，WXML `wx:for` 渲染，输入/点击都是原生 setData 路径。
- **防御式兼容三件套**（检索不可用时的通用策略）：typeof 探测降级、失败 toast 说明具体 URL/原因、配置一处改（config.js LAN_IP）。
- **test/ 双脚本可反复跑**：`node test/api.test.js`（60 断言）+ `python test/wxml_check.py`（结构校验写 report.txt），交付/改动后各跑一遍。
