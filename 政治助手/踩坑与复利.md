# 踩坑与复利（政治助手）

格式参考全局库《使用说明与模板》。开工日期 2026-11-03。

## 开工前要避的坑（来自全局 records.json）
- [G-0001] PS5.1 读 UTF-8 中文必须显式编码；控制台输出 GBK 会花 → **方案：脚本内部输出一律写 UTF-8 文件再 Read，不在控制台读中文**。
- [G-0005] JSON 一律程序序列化生成，不手写含路径 JSON。
- [G-0006] .bat 只写 ASCII 注释。
- [G-0002] 后台进程要落崩溃日志 → Flask 全局 errorhandler 写 logs/error.log。
- [G-0026] 手工拼 multipart 请求时收尾边界前必须有 CRLF，且文件名只用 ASCII（见踩坑 11）。
- [G-0027] 管道函数里行级 `except Exception: continue` 必须配日志，否则整批结果无声变空（见踩坑 12）。
- [G-0028] 修改常驻服务代码后必须杀进程重启再测，否则全部测试打到旧代码上出假结果（见踩坑 13）。

## 实际踩坑记录
1. **Windows 自带 OCR 中文质量差（已在用户机器实测）**
   - 现象：逐字碎开加空格、"方法论"→"氵去论"、"错误"→"钅昔误"、数字"-"→"一"；字符级相似度 93.7%，且行结构还需清理。
   - 对照：RapidOCR（PaddleOCR 模型 + onnxruntime）同图 100.0% 全对、稳定 1.2s/张（CPU）。
   - 决策：主引擎 RapidOCR，Windows OCR 留作兜底（`/api/ocr?mode=win`）。
   - 复测脚本：`test/check_acc.py` → 结果 `test/ocr_compare-result.txt`。
2. **控制台 GBK 乱码**：python/PowerShell 打中文进管道必花。**对策**：所有对比/验证脚本的输出写 UTF-8 文件，用编辑器读。这在本仓库是硬规则。
3. **pip 国内安装**：`pip install rapidocr_onnxruntime -i https://pypi.tuna.tsinghua.edu.cn/simple`，模型已捆绑在 wheel 里装完即离线可用，首次运行无需联网下载模型。
4. **Flask 上传中文文件名**：统一不信任原名，时限 `时间戳+uuid` 存 screenshots/，避免编码/路径注入问题。
5. **f-string 吞 `{{}}` 标记（已修）**：种子脚本用 f-string 拼 `{{!词}}` 被转义成单花括号，前端挖空全失效；接口返回里肉眼比对才发现。规矩：含自定义双花括号标记的文本一律 `+` 拼接，生成后断言标记数。已蒸馏 G-0021。
6. **PS5.1 的 curl 是别名**：显式 `curl.exe`，且结果 -o 落文件再读。已蒸馏 G-0022（同上 G-0020 也已入全局库）。
7. **功能做了≠入口存在（产品级教训）**：inbox 自动扫描、整理页都上线了，但界面上没任何提示，用户第一反应"没有入口传不了截图"。规矩：每个新能力必须在 1 张首页视口内找到入口或引导；上线前用"假装第一次打开"自检一遍。修复：底部四 Tab + ❓使用指北页 + 列表尾部输入通道卡片 + 空态大按钮。
8. **文件指纹死链 = 新型"吞文件"（重要）**：丢过的图，草稿被确认/丢弃后 processed.json 里的 md5→草稿ID 变成死链；同一文件再丢被指纹静默跳过——没草稿、没记录，用户全程无感。修复：丢弃草稿 →「已忽略」面板留痕（带 hash，可转回草稿）＋「♻️全量重扫」释放全部指纹兜底。规律：**任何"处理过"的判定都要配可见记录 + 人工释放通道**。已蒸馏 G-0023。
9. **查重必须考虑生成标记**：词条文本带 `{{!词}}` 标记，与 OCR 原文归一化对比时若不剥掉 `{}`/`!` 就永远对不上（包含判定失败）。norm_text 白名单补 `{}`。教训：做内容比对先列一份"本系统会给文本贴什么装饰"的清单。
10. **文档提字=在截图管道上加分支**：IMG_EXTS+DOC_EXTS 白名单；PDF 逐页"文字层优先、空白页 pypdfium2 渲图走 RapidOCR"混合；OCR 页数上限 40/份 + 2万字截断，防后台扫描线程被大文件卡死。测试时用 PIL ImageDraw(msyh.ttc) 画字生成无文字层 PDF 打 OCR 兜底路径。已蒸馏 G-0024。
11. **手工 multipart 双坑（排查半天）**：① 收尾边界 `'--b--'` 前少了 `\r\n`，werkzeug 解析失败把整个 part 静默丢弃 → 服务端报 `no file`（HTTP 400），客户端还以为字段名错了；对照最小探针（带 `\r\n--b--`）全过才定位。② 文件头里塞中文文件名同样导致解析不到文件。已蒸馏 G-0026。
12. **行级 except 吞异常 = 无声全空（重要）**：`_red_rows` 里每行 `except Exception: continue`，而 PIL box 坐标是浮点，直接进 `range()` 抛 TypeError → **所有行全崩进 except，红标结果全空但零报错**，表现为"OCR 正常、红标为 0"，一度被误判成阈值问题。修复：box 坐标先 int；行级异常写 `logs/error.log`（`[red-rows]` 前缀）。规律：**逐元素循环里的裸 continue 必须配日志，且新功能要有"输出非空自检"**（测试断言红标数 > 0 而不是只断言HTTP 200）。已蒸馏 G-0027。
13. **改服务代码不重启 = 测试全假绿/全假红**：Flask 常驻后台进程持有旧代码，连续多轮测试全打到过期进程上，新逻辑"修好了还在坏"。修复流程固化：`ast.parse 语法检查 → Get-CimInstance 杀 server.py 进程 → 后台重启 → 再跑测试`。已蒸馏 G-0028。
14. **截图红标自动复用（复利主菜）**：用户截图里老师已有的红字/红下划线/红框直接当背题挖空点，不让用户重复劳动——OCR 同行碎片按 `yc∈0.6h 归并 + x 排序` 合成整行再逐字采样红色占比（正文/基线/框外三带，下划线沉在检测框外要下探 0.35 行高），段内允许夹单个标点（「文化强国、体育强国」不切断）、段缘剥杂符、少于 2 个实义字的段丢弃。库里无标注的历史词条用 difflib 相似度(≥0.50)反向找回源图，用**当时最新引擎**重出带挖空文本（顺带修复旧 OCR 乱序）——数据修复脚本 `test/remark_entries.py` 支持 FORCE_REDO 白名单，绝不允许覆盖用户手动编辑过的词条。已蒸馏 G-0025。
15. **界面骨架注入三坑（手机版式翻修全中）**：① 底栏 `<a>` 没包 `<nav class="bnav">` 时 CSS 全落空，页面变成裸链接；② 壳容器 `#chromeTop/#chromeBottom` 写在 `<script>` 之后、或页面根本没调 `mountChrome()`（manage.html 中招），JS 都是**静默跳过零报错**；③ 外层 `.stickrow` 手机折行后，内层 `.grp`（flex:0 0 auto）仍是 447px 整体不可折，且搜索框 `width:100%` 写在 auto 宽的内层 flex 里解析不出内容宽——双层 flex 都要允许折行，搜索组 `flex:1 1 100%` 独占一行才稳。验证手法：无设备模拟 → 同源 iframe 壳 390px 宽（媒体查询按 iframe 宽度触发）；壳本身是 flex 布局时 inline width 会被压回 `flex-shrink:1` 的计算值，要显式 `flex:0 0 auto`。发给手机 PWA 的 CSS/JS 一律带 `?v=` 缓存戳 + Flask `SEND_FILE_MAX_AGE_DEFAULT=0`，否则 304 让手机永远用旧样式。已蒸馏 G-0029。

## 复利
- **两段式提字流**：机器 OCR 给初稿 → 人工在录入页校对+挖空标红 → 存库。识别不准时降级路径三种（手动修改 / mode=win / 手打）。
- **间隔复习**：简化 Leitner（1/2/4/7/15/30/45 天），背错即归零明天再见，不引入复杂 SRS，够用。
- **的手机即用方案**：0.0.0.0 锚定 + DPI 引导二维码（/qr.svg）+ 响应式三页 SPA + "添加到主屏幕"；先局域网，将来公网只需把端口暴露/反代，服务端零改动。
